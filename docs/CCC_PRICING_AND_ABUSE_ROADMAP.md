# CCC 상품 가격정책 및 무료 이용 악용 방지 로드맵

- 지시: CCC-SUPERVISION-20260921-09 / 2026-09-21 PHT
- 상태: **ROADMAP_RECORDED / IMPLEMENTATION_NOT_STARTED**. 요금제·결제·중복 이용 방지가 운영 서버에 적용됐다는 뜻이 아니다.
- 사용자 확정 요구: “무료사용자 시작 시드 금액은 500불 이후 증거금을 증액하려면 유료 결제로 전환”, “1인이 여러개의 계정을 이용하여 무료 사용을 악용하는 경우” 대비.
- 기존 개인용 CCC에 **향후 무료·유료 사용자 상품화 계획**을 추가한다. 과거의 ‘외부 고객용 SaaS가 아님’은 현재 운영 범위에 관한 설명이며, 이 상품화 로드맵을 배제하는 근거로 사용하지 않는다.

## 상품 기준

| 항목 | 로드맵 기준 | 상태 |

현재 가상 서비스에서는 $500를 **가상 시드**로 설계한다. 실제 현금·USDC를 회사가 지급하거나 인출 가능한 보너스를 제공한다는 의미가 아니다. 미래 LIVE는 사용자 본인 자금과 별도 운용 권한을 전제로 하며 이번 지시로 활성화하지 않는다.

아래 항목은 혼란과 우회 이용을 막기 위한 **권고 세부 정책**이며 가격·환불 조건처럼 아직 사용자가 정하지 않은 사항은 공개 약관과 요금제 확정 전 검토한다.

- 한도는 계정 평가액이나 레버리지를 곱한 명목 포지션 금액이 아닌 **이용권에 배정한 운용 원금** 기준이다. 상품 $500와 주문별 증거금/노출 상한은 서로 다른 값이며 유료 전환도 기존 Risk/손실/보호 한도를 우회하지 않는다.
- 매매 수익 때문에 평가액이 $500를 넘는 경우 유료 전환을 강요하거나 자동 과금하지 않는다. 현재 자동복리 제한도 유지한다. 수익의 추가 운용 원금 편입은 별도 증액 정책으로 다룬다.
- 무료 배정은 1인당 한 번 기록한다. 손실 후 재가입, 새 이메일·지갑 연결, 브라우저 초기화로 새 $500를 받지 못한다. 체험용 REPLAY 리셋을 제공하더라도 무료 운용 원장과 분리하며 성과를 초기화하지 않는다.
- 여러 계정 사용 자체보다 **무료 혜택의 중복 수령**을 제한한다. 동일 이용자의 계정·지갑 간 무료 배정 합계는 $500 이하이며 예를 들어 $300+$300은 허용하지 않는다. 이용권을 연결해도 거래 원장이나 자금을 임의 합치지 않는다.
- 출금 후 재입금, 가상 시드 반환·재배정, 탈퇴 후 재가입, 유료 해지 후 무료 복귀 때 누적 배정액을 어떻게 계산할지 상용 개방 전 확정한다. 확정 전에는 삭제·재가입으로 무료 배정 이력을 지우거나 재발급하지 않는다. 개인정보 삭제와 부정 이용 최소 기록의 보관·삭제 기준도 함께 정한다.

## 무료 시드 악용 방지 설계

| 통제 | 적용 방식 | 오탐·비용 통제 |
| --- | --- | --- |
| 서버 배정 원장 | person/entitlement/claim ID와 배정·회수 이력을 영속 저장. 동시 가입·재시도에도 트랜잭션/고유 제약으로 한 번만 배정 | 클라이언트 localStorage와 이메일만으로 한도 판정 금지 |
| 기본 가입 보호 | 이메일 인증, 가입/시드 신청 속도 제한, 필요 시 봇 방지 challenge를 서버에서 검증 | 봇 통과를 동일인 증명으로 취급하지 않음 |
| 위험 신호 조합 | 반복 시드 신청, 연결된 계정·소유권 확인 지갑, 자동화 패턴 등 근거를 조합 | IP·기기·이메일 도메인 하나만으로 동일인 확정/영구 차단 금지 |
| 단계적 추가 확인 | 의심 시 추가 인증/휴대폰 확인 또는 운영자 검토. 지갑을 쓰는 흐름은 nonce 기반 소유권 확인 | PAPER에 지갑·유료 SMS·KYC 일괄 강제하지 않음. 공유/재사용 전화번호 예외 검토 |

| 감사와 개인정보 | 판정 근거, 적용 규칙 버전, 검토/해제 이력, 접근 권한과 최소 보관기간 설계 | 불필요한 신분증·침습적 기기 추적 기본 수집 금지. 개인정보 정책은 출시 지역/사업자에 맞춰 확인 |

이메일·전화·IP·지갑 어느 하나도 ‘전세계 1인 1계정’을 완벽히 증명하지 않는다. 목표는 반복 획득 비용을 높이고 중복 배정을 탐지·제한하는 것이다. 악용률, 오탐 이의제기/복구율, 인증 이탈, 검토 시간과 인증 비용을 관측하며 100% 방지로 홍보하지 않는다.

부정 이용 의심이나 결제 취소로 기존 포지션의 보호/정상 청산/정산/조회가 중단되지 않게 한다. 실제 자금의 몰수·출금 봉쇄·일괄 강제 청산으로 무료 이용 통제를 구현하지 않는다.

## 결제와 증액 경로

1. 화면에 무료 배정 원금, 현재 평가액/손익, 추가 배정 요청액, 적용 이용권을 구분한다. ‘증거금 증액’ 요청 때 가격과 조건을 제시하고 사용자가 결제를 선택한다.
2. 추가 배정은 서버의 유효 이용권 및 남은 한도를 검사한다. UI 비활성화만으로 제한하지 않으며 API/worker 등 모든 배정 경로를 동일 서비스로 통일한다.
3. 결제 완료 redirect나 클라이언트 성공 메시지를 권한 증거로 사용하지 않는다. 사업자 서명 검증, 이벤트 중복 처리 방지, 순서 역전/재전송 대응, 최신 구독 상태 대조 후 원자적으로 이용권을 갱신한다. 확인이 안 되면 추가 배정은 대기시키고 기존 포지션 관리는 계속한다.
4. 동시 요청과 결제 이벤트 재처리로 이용권·시드가 두 번 증가하지 않아야 한다. 증액/취소/정정은 감사 원장에 남기며 기존 거래 손익을 수정하지 않는다.
5. 해지·환불·결제 실패 시 신규 증액을 제한하는 상태와 기존 포지션 관리 상태를 분리한다. 초과 원금의 축소 시점, 유예기간, 무료 복귀 자격은 요금제 확정 때 결정하고 사전 안내한다. 자동 강제 청산을 기본 해지 처리로 쓰지 않는다.

결제 사업자는 미선정이다. 아래 Stripe 문서는 구현 참고이며 CCC의 사업자 국가·상품·가상자산 관련 사용 사례에 대한 이용 가능성이나 계약 승인을 확인했다는 뜻이 아니다. 이번 로드맵은 유료 서비스 가입·실결제·예산 증액 승인이 아니다.

## 사업성 판단과 비용 제한

**조건부 추천:** $500 무료 체험은 진입 장벽을 낮추지만 가상 증거금 증액만으로 지불 의사가 충분한지는 아직 검증되지 않았다. 기존 가상 매매의 신뢰성과 사용성을 먼저 검증한 후 체험→유료 전환율과 지불 의사를 측정한다. 강제 손익 연출이나 위험 한도 완화를 전환 장치로 쓰지 않는다.

다중 계정 차단만으로 운영비가 제한되지는 않는다. 무료 활성 사용자당 서버/API/저장/인증/지원 비용을 측정하고, 모집 인원·가입 속도·분석 요청·보관기간에 대한 무료 사용량/예산 상한을 정한다. 시장 데이터와 계정에 무관한 분석은 적절히 공유 캐시하되 계정별 판단·권한·원장은 격리한다. 보호와 정산에 필요한 작업을 절감 대상으로 삼지 않는다.

유료 1인 공헌이익 = 결제 순매출 − 해당 사용자의 변동 운영비. 무료 활성 사용자 비용과 고정비를 이 공헌이익으로 감당할 수 있는지 확인한다. 아직 측정값·가격이 없어 손익분기 인원이나 수익성을 확정하지 않는다. 초기에는 기본 보호와 위험 기반 추가 확인으로 시작하고, 전면 유료 KYC/SMS/신규 외부 분석 도입은 비용·효과를 비교한 뒤 판단한다. 요금/기능 플래그와 단계적 참가자 확대를 통해 되돌릴 수 있게 출시한다.

## 수용 시험 목록 — 아직 실행하지 않음

- 첫 무료 신청 정확히 $500, 추가 $0.01 배정은 유효 유료 권한 없이 거절. 평가이익으로 $500 초과는 과금/자동 증액 없이 유지.
- 재시작·브라우저 종료·재가입·이메일/지갑 변경·동시 신청·API 직접 호출로 재배정 불가. 동일 이용자 $300+$300 시도 거절.
- 서로 다른 정당한 사용자가 같은 IP/기기/전화번호 위험 신호 때문에 영구 차단되지 않고 추가 확인·이의제기로 복구 가능.
- 다른 계정 ID를 삽입해 잔액/판단/정산 조회, 설정 변경, 시드 배정 또는 주문 실행 불가. 각 계정의 worker/원장/캐시 격리 검증.
- 위조·중복·순서 역전 webhook, 결제 실패/지연/환불/해지 중복 처리에도 잘못된 증액 불가. 결제 대기·해지 시 기존 보호·청산·정산 유지.
- 가상 시드/실지갑/배정 원금/손익/레버리지/주문 증거금이 화면과 원장에서 혼동되지 않음. 기존 Virtual400 세션·원금·손익·HWM과 5–10배 정책 보존.
- 운영비·악용/오탐·인증 이탈 관측, 검토/삭제/이의제기 처리와 출시 중단·복귀 절차 확인.

## 설계 참고 자료

- [Cloudflare Turnstile 서버 검증](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/): challenge 응답은 서버 검증이 필요하며 단회 토큰·재사용 거절을 지원한다. 동일인 식별 기능으로 간주하지 않는다.
- [Stripe Webhooks](https://docs.stripe.com/webhooks): 서명 검증, 중복 이벤트 및 전달 순서 비보장에 대응하는 결제 이벤트 처리 참고. 사업자 채택 결정은 별도다.

## 시간별 감독에 반영할 상태

이 문서를 최신 상품 요구로 읽고 P0 일정·실제 증거 보고에 상품화 단계/담당/다음 작업/기한 영향/미정 가격과 비용을 포함한다. 문서 완료를 결제·악용 방지 구현 완료로 세지 않는다. P0가 지연 중이면 상품화를 명분으로 해당 복구를 중단하거나 별도 시스템을 새로 만들지 않는다.
